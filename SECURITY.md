# Security policy

Technocore Foundry is an independent community preview. Please do not include private keys,
passphrases, access tokens, encrypted vaults, unpublished receipts, raw proof exports, or personal
data in a vulnerability report. Redact public-message evidence to the smallest reproducer needed.

Report security issues through [GitHub private vulnerability reporting](https://github.com/mehmetkr-31/technocore-foundry/security/advisories/new).
Do not open a public issue for an undisclosed vulnerability. This preview currently has no response
SLA; reports will be handled on a best-effort basis.

The source repository is public. The hosted application remains owner-only, so this policy does
not announce or authorize public service access. The Technocore readiness write path is intended
only for a loopback-local node and explicit operator actions; it is not a hosted public relay.

The current audit, enforced boundaries, regression commands, and residual risks are documented in
[`release/SECURITY_AUDIT.md`](release/SECURITY_AUDIT.md). The operating and upstream-review trust
boundaries are documented in
[`docs/TECHNOCORE_READINESS.md`](docs/TECHNOCORE_READINESS.md), and the protocol threat model is
[`protocol/THREAT_MODEL.md`](protocol/THREAT_MODEL.md). A valid signature is not proof of truth,
sole authorship, identity, server inclusion, reward entitlement, or airdrop eligibility.
